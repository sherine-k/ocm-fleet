Refactor the TypeScript fleetctl CLI to separate command execution from
output presentation.

Commands currently mix fetching data, selecting an output format, and
rendering through Ink. JSON and plain text are written from React effects,
stdout writes are not awaited, and some commands ignore --output json.
Under CI, JSON output can acquire an extra blank line.

Desired design:

- Leaf command modules export plain CommandSpec<Data> definitions with a
  strongly typed runner and an optional human presenter. The presenter
  consumes the runner's data and returns a string or React element.
  Register these definitions in command-group indexes.
- Registered commands expose their full specification through a generic
  visitor:
  withSpec<Result>(visit: <Data>(spec: CommandSpec<Data>) => Result): Result;
  Preserve the runner/presenter type relationship through registration and
  dispatch, including commands with different result shapes. Mismatched
  types should fail typechecking.
- Shared execution selects human presentation or JSON serialization and
  returns Promise<string | ReactElement>, without performing output I/O.
  Shared output infrastructure writes the resulting output.
- JSON output serializes command data directly, bypassing human presenters
  and Ink. Writes are awaited and append exactly one newline.
- Human output preserves existing tables, schema text, and useful messages.
  Commands without a human presenter fall back to JSON.
- React hooks remain inside components.
- Every implemented command honors --output json, including resource types,
  resource describe, and commands returning success messages.

Update the affected commands, shared infrastructure, tests, and relevant
documentation. Follow existing command organization and repository
conventions.

Add focused regression tests for output selection, exact JSON bytes under
CI=true and CI=false, human rendering, awaited stream completion, and stream
errors. Include compile-time coverage for the runner/presenter contract.
Include regression tests that invoke the built CLI for a data-returning
command and a success-message command. Under both CI=true and CI=false,
assert complete stdout, including exactly one trailing newline. Include a
human-output regression case. Use local fixtures without requiring a live
management backend.

Validate with the applicable local CLI tests, typechecking, lint, and build.
Resolve implementation and validation failures within this scope.

Finish with a concise description of the changes, validation results, and
any remaining limitations.
